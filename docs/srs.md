# SRS

## Введение

### 1.1. Назначение

SRS предназначена для определения поведения системы, условий ее работы и критериев проверки реализации.

### 1.2. Область применения

Page Mates предназначен для пользователей от 18 до 40 лет, которые ведут учет чтения книг и хотят обсуждать книги с другими читателями в процессе чтения.

В состав системы входят:

- управление пользовательским аккаунтом и профилем
- читательский дневник (книжный трекер)
- учет прогресса чтения
- заметки, цитаты и теги
- поиск и просмотр тематических тредов
- защита от спойлеров на основе прогресса чтения
- отслеживание тредов
- социальное взаимодействие между пользователями
- Premium-возможность создания тредов

В приложение не входят электронное или аудио чтение книг, собственный каталог книг и организация очных книжных встреч.

## Общее описание

### 2.1. Пользователи

#### Обычный пользователь

Может создавать записи о книгах, вести прогресс чтения, добавлять заметки, цитаты и теги, находить и просматривать доступные треды, отслеживать треды и взаимодействовать с другими пользователями.

#### Premium-пользователь

Имеет все возможности обычного пользователя и может создавать тематические треды.

### 2.2. Допущения

- Пользователь самостоятельно вводит название книги и другие сведения о ней
- Система не содержит собственной базы книг
- Для поиска связанных обсуждений используется название книги, указанное пользователем
- Для расчета прогресса пользователь указывает общее количество страниц и количество прочитанных страниц
- Пользователь самостоятельно включает или отключает защиту от спойлеров
- Для использования социальных функций пользователь должен иметь аккаунт

### 2.3. Зависимости

- Работа социальных функций и синхронизация данных требуют подключения к Интернету
- Для регистрации и авторизации требуется доступ к backend-сервису Page Mates
- Для поиска тредов система использует данные, созданные пользователями
- Создание тредов зависит от наличия у пользователя активного Premium-статуса

### 2.4. Ограничения

- MVP реализуется как Android-приложение
- Пользователь должен быть не младше 18 лет
- Система не предоставляет содержимое книг
- Система не создает автоматически карточки книг из внешнего каталога
- Доступность тредов при включенной защите от спойлеров определяется числовым прогрессом книги

## Функциональные требования

### 3.1. Аккаунт и профиль

#### FR-01. Регистрация

**Требование:**

Система должна позволять пользователю создать аккаунт с уникальным идентификатором пользователя и данными, необходимыми для авторизации.

**Критерий приемки:**

- Сначала пользователь не имеет аккаунта
- Когда пользователь вводит корректные регистрационные данные, система создает аккаунт и предоставляет возможность авторизации

#### FR-02. Авторизация

**Требование:**

Система должна позволять зарегистрированному пользователю авторизоваться в приложении.

**Критерий приемки:**

- Существует зарегистрированный пользователь
- Когда он вводит корректные данные авторизации, система авторизует пользователя и предоставляет доступ к его данным

#### FR-03. Профиль пользователя

**Требование:**

Система должна позволять пользователю просматривать и изменять свой профиль.

Профиль должен поддерживать как минимум:

- имя
- аватар
- информацию о пользователе
- список любимых книг

**Критерий приемки:**

- Если пользователь авторизован, то, когда он изменяет данные профиля и сохраняет изменения, при повторном открытии профиля отображаются сохраненные данные

### 3.2. Книжный трекер

#### FR-04. Добавление книги

**Требование:**

Система должна позволять пользователю самостоятельно создать запись о книге.

При создании пользователь должен иметь возможность указать:

- название
- автора
- количество страниц
- статус чтения
- теги
- изображение
- заметки
- цитаты

**Критерий приемки:**

- Если пользователь авторизован, то, когда он заполняет обязательные данные книги и сохраняет запись, книга появляется в его трекере

#### FR-05. Изменение записи о книге

**Требование:**

Система должна позволять пользователю изменять данные созданной им записи о книге.

**Критерий приемки:**

- Если книга находится в трекере пользователя, то, когда пользователь изменяет данные книги и сохраняет изменения, в трекере отображаются новые значения

#### FR-06. Статус книги

**Требование:**

Система должна позволять пользователю устанавливать и изменять статус книги.

Набор статусов:

- запланирована
- читается
- прочитана

**Критерий приемки:**

- Если книга добавлена в трекер, то, когда пользователь выбирает новый статус, выбранный статус сохраняется и отображается в записи книги

#### FR-07. Прогресс чтения

**Требование:**

Система должна позволять пользователю указывать количество прочитанных страниц и вычислять процент прогресса по формуле:

`Прогресс = прочитанные страницы / общее количество страниц x 100%`

Количество прочитанных страниц не должно превышать общее количество страниц.

**Критерий приемки:**

- Если книга содержит 140 страниц, и пользователь указывает 70 прочитанных страниц, то система отображает прогресс 50%

#### FR-08. Записи о прогрессе

**Требование:**

Система должна позволять пользователю изменять количество прочитанных страниц в процессе чтения.

**Критерий приемки:**

- Если прогресс книги составляет 50%, и пользователь изменяет количество прочитанных страниц до значения, соответствующего 70%, то система отображает прогресс 70%

#### FR-09. Заметки и цитаты

**Требование:**

Система должна позволять пользователю создавать, изменять и удалять личные заметки и цитаты, связанные с книгой.

**Критерий приемки:**

- Если книга находится в трекере, и пользователь создает заметку или цитату и сохраняет ее, то запись отображается в соответствующей книге

#### FR-10. Теги

**Требование:**

Система должна позволять пользователю добавлять и удалять теги у книг.

**Критерий приемки:**

- Если книга находится в трекере, и пользователь добавляет тег, то он отображается у книги после сохранения
- Если книга находится в трекере, и пользователь удаляет существующий тег, то он отображается у книги после сохранения

### 3.3. Обсуждения

#### FR-11. Поиск тредов по книге

**Требование:**

Система должна предоставлять пользователю возможность найти треды по названию книги.

**Критерий приемки:**

- Если пользователь указал в трекере название "Война и мир", то система выполняет поиск обсуждений по названию, и пользователю отображаются треды, связанные с соответствующим названием книги

#### FR-12. Просмотр треда

**Требование:**

Система должна позволять пользователю просматривать доступные ему треды и сообщения в них.

**Критерий приемки:**

- Если тред доступен пользователю, и пользователь открывает тред, то система отображает его название и сообщения

#### FR-13. Комментирование треда

**Требование:**

Система должна позволять пользователю оставлять сообщения в доступных ему тредах.

**Критерий приемки:**

- Если тред доступен пользователю, и пользователь открывает тред, то пользователь имеет возможность оставлять в нем сообщения

#### FR-14. Прогресс треда

**Требование:**

При создании треда Premium-пользователь должен иметь возможность указать уровень прогресса книги, к которому относится обсуждение.

Тред также может быть обозначен как обсуждение всей книги. Для такого треда уровень прогресса должен составлять 100%.

**Критерий приемки:**

- Если Premium-пользователь создает тред, и он указывает уровень прогресса 60%, то тред сохраняется с уровнем прогресса 60%

#### FR-15. Создание треда

**Требование:**

Система должна разрешать создание новых тредов только пользователям с активным Premium-статусом.

**Критерий приемки:**

- Если пользователь имеет активный Premium, и он создает тред с корректными данными, то система сохраняет и публикует тред
- Если пользователь не имеет Premium-подписки, и он пытается создать тред, то система не создает тред и сообщает о необходимости Premium

#### FR-16. Защита от спойлеров

**Требование:**

Система должна позволять пользователю включить или отключить защиту от спойлеров.

При включенной защите система должна показывать только те треды, уровень прогресса которых меньше либо равен текущему прогрессу пользователя по соответствующей книге минус 5%.

**Критерий приемки:**

- Если пользователь прочитал 70 из 140 страниц, и защита от спойлеров включена, то при открытии списка тредов книги система показывает треды с уровнем прогресса только от 0% до 45%

#### FR-17. Доступ к обсуждению всей книги

**Требование:**

При включенной защите от спойлеров система должна предоставлять доступ к тредам всей книги только после достижения пользователем 100% прогресса.

**Критерий приемки:**

- Если тред относится ко всей книге и имеет уровень прогресса 100%, и пользователь имеет прогресс менее 100%, то тред не отображается среди доступных
- Когда пользователь достигает 100%, тред становится доступным

#### FR-18. Отслеживание треда

**Требование:**

Система должна позволять пользователю начать или прекратить отслеживание доступного треда.

**Критерий приемки:**

- Если пользователь просматривает доступный тред и выбирает действие "Отслеживать", то тред добавляется в список отслеживаемых
- Когда пользователь прекращает отслеживание, тред удаляется из этого списка

### 3.4. Социальное взаимодействие

#### FR-19. Друзья

**Требование:**

Система должна позволять пользователю добавлять других пользователей в друзья и удалять их из списка друзей.

**Критерий приемки:**

- Если пользователь открывает профиль другого пользователя и выбирает действие добавления в друзья, то другой пользователь появляется в его списке друзей

#### FR-20. Отслеживание тредов пользователей

**Требование:**

Система должна позволять пользователю отслеживать треды, созданные другими пользователями.

**Критерий приемки:**

- Если пользователь открыл профиль другого пользователя и выбирает отслеживать треды, то треды, созданные этим пользователем, появляются в списке отслеживаемых тредов

## Нефункциональные требования

### NFR-01. Производительность

Основные операции приложения, не требующие загрузки больших объемов данных, должны получать ответ от backend-сервиса не более чем за 2 секунды в 95% запросов при нормальной нагрузке MVP.

### NFR-02. Поиск

Поиск тредов по названию книги должен возвращать результат не более чем за 2 секунды в 95% запросов при нормальной нагрузке MVP.

### NFR-03. Надежность сохранения данных

После успешного сохранения данных книги, прогресса, заметки, цитаты или другого пользовательского объекта данные не должны теряться при повторной авторизации пользователя.

### NFR-04. Безопасность авторизации

Система не должна предоставлять пользователю доступ к личным данным или операциям другого пользователя без соответствующих прав.

### NFR-05. Защита пользовательских данных

Доступ к данным пользователя должен осуществляться только после его авторизации. Данные, доступные только владельцу, не должны отображаться другим пользователям.

### NFR-06. Защита от спойлеров

При включенной пользователем защите от спойлеров система не должна отображать пользователю тред, уровень прогресса которого превышает текущий прогресс пользователя по соответствующей книге.

### NFR-07. Доступность

Backend-сервис Page Mates должен обеспечивать доступность не менее 99% времени в течение календарного месяца, за исключением заранее запланированных технических работ.

### NFR-08. Валидация данных

Система должна отклонять некорректные значения:

- количество страниц меньше или равно 0
- количество прочитанных страниц меньше 0
- количество прочитанных страниц больше общего количества страниц
- прогресс меньше 0% или больше 100%

Пользователь должен получить сообщение о причине отклонения данных.

### NFR-09. Совместимость

MVP должен поддерживать устройства на Android с версией ОС, определенной командой как минимальная поддерживаемая версия на момент выпуска.

### NFR-10. Возрастное ограничение

Система должна ограничивать регистрацию пользователей возрастом 18 лет и старше.

## Проверяемость требований

Каждое функциональное и нефункциональное требование имеет уникальный идентификатор и проверяемый критерий выполнения.

Требования FR-01 - FR-19 и NFR-01 - NFR-10 должны быть покрыты пользовательскими историями и тестами в RTM.

Для каждого требования в RTM должна быть указана связь между бизнес-целью PRD, User Story, требованием SRS и тестом или метрикой.
